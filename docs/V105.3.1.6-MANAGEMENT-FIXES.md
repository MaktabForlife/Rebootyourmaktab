# V105.3.1.6 — Management testing fixes

## Scope

This patch finishes issues reported during testing. The shared academy User Profile/role tool is V105.3.2; timetable development is V105.3.3; library/resources V105.4; student/program integration including tasks V105.5. Existing Learners remains a class-enrolment editor for this release.

## Behavior

- Overview uses native keyboard-accessible disclosures for subjects, levels and modules. Each starts collapsed on page load. Modules without a level sit directly beneath the subject. Expanding a parent does not automatically expand its children. Search filters matching records but leaves expansion to the user; expansion choices survive rerendering within the current page.
- An unfinished row or pending save no longer blocks browsing another management tab. Other sections are read-only until that entry is completed or explicitly cancelled. Return to unfinished entry restores its section. Retry from another section still targets the original pending operation. Drafts retain their original comparison baseline through refresh and navigation.
- Learners offers Add learner for existing academy accounts and explains prerequisites such as an active class. Profile editing and role assignment remain deferred to V105.3.2.
- Teacher candidates require active accounts and a current Teacher, Senior or Admin grant in this Program. A role in another Program or platform administration alone does not qualify. Backend validation enforces the same rule. Old explicit teacher assignments cannot override revoked program roles, and may still be archived. Existing records are not automatically rewritten.
- Login and all Program version badges, both version files and Worker health report V105.3.1.6.

## Spreadsheet failures and load

Management refresh requests management data plus overview together. The server shares one management snapshot and request-local read cache rather than repeating authentication/program/reference reads in three requests. In the synthetic Sheets integration fixture the previous manage-get/get/preview flow uses 36 upstream reads; the combined flow uses 13. This is a measured fixture result, not a guarantee for every real dataset.

Google Sheets 429, access/auth/not-found errors, temporary service errors and unexpected backend exceptions have distinct error codes and safe messages. Correlated logs include action, processing stage, upstream status and stack locations, without upstream response text, user rows or credentials. Development Worker observability is enabled. Confirmed saves followed by refresh failure remain reported as saved. Retryable uncertain saves wait before one automatic recovery/retry; a rate limit waits 60 seconds. Persistent failures retain the exact pending operation. Configuration/access errors do not trigger an automatic retry loop.

The exact cause of the user's earlier error remains unconfirmed. The release reduces redundant reads and provides evidence for future diagnosis; it does not claim a confirmed quota exhaustion diagnosis or a database migration.

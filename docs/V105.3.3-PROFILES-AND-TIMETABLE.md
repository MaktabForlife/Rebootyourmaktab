# V105.3.3 — User profiles and timetable

Development targets: `feature/v105.2-program-timetable`, `maktab-development` and `devrebootworker`. Main and the live site are outside this release.

## User profiles

Administrators can open and edit multiple name/status and role cells. Changes persist in the tab's session across refresh/reload. Save all submits changed user entries in bounded groups of 20; a row Save icon saves that user's changes. Each group is validated before one atomic Google Sheets batch write, with merged updates to the same matrix row, one audit record and a recoverable receipt. If a group fails, confirmed groups remain saved and the failed/later entries remain pending. Opening an unchanged cell does not cause a Save all write.

The server accepts up to 80 entries per group and 128 KiB per request; the existing 45,000-character receipt limit still rejects an oversized save before any write. Profiles are validated before roles so account reactivation and role additions can be saved together. All reads, writes, batch actions and recovery continue to require an active academy administrator. Per-scope Admin cannot grant academy-wide authority. Credentials and stable account identities are not editable.

Column-wide Free/Paid policy changes retain their separate explicit confirmation and Save access setting action. They are not mixed into user-row batches. Roles can still be combined. View opens saved profile details in a dialog; Share and Copy obtain the account's existing personal sign-in link. Sharing uses the device share sheet when available and otherwise copies/shows the link. New accounts remain pinned for the browser-tab session.

## Teacher eligibility and access boundaries

Once the academy matrix is prepared, active users with confirmed Teacher, Senior or Admin roles in the selected program supply timetable teachers and management role displays. A removed matrix role does not fall back to an old elevated UserCourseAccess role. Imported entries marked REQUIRED are excluded until confirmed. Before any matrix setup, the legacy reader remains available for compatibility; a partially configured matrix fails explicitly.

This is a narrow integration for program teaching eligibility. Global Subject/Reboot runtime authorization and their legacy records are unchanged. Free/Paid enforcement migration is not silently activated by this release. Earlier user observations on access and enrolments remain provisional pending their later tests.

## Subjects and lessons

In Subjects, Edit now exposes the existing Academy subject name. Renaming updates AcademySubjectList using the same SubjectID, protects against duplicates and detects concurrent renames. The UI preserves the proposed name and asks which version to use for a conflict. The rename and program-row save are separate, retryable phases because they use separate workbooks/coordinators. A confirmed rename remains saved if the later program-status write fails; retries resume that remaining phase. Published snapshot names remain historical.

The timetable's Subject / Module selector supports active subjects linked to the program without requiring a module. Subject-only rules retain ProgramSubjectID and never create a module-completion record. Modules still resolve their optional level and subject. Classes, optional eligible teacher, weekdays, time validation, membership clashes and Zoom precedence remain enforced. Multi-class lessons still require one shared lesson link.

## Reuse and publication

Each Published history entry offers Edit as new version. It copies editable fields into the draft, carrying over the published effective Zoom links so a changed class default cannot silently alter the copied meeting. An unfinished local draft must first be saved or kept; it is not silently replaced. Older dated publications retain the existing explicit conversion review for one-off lessons/exceptions.

Copying does not publish. Preview checks current subjects, classes and teacher eligibility. Publish appends a new immutable version with today's or a future effective date. Original publications are never edited.

## Preview, image and PDF

The supplied Aalimiyah PDF is a layout reference: academy/program/class heading, purple weekdays across the top, time ranges down the left, module/subject names and teachers inside cells. The old schedule, names and meeting credentials are not imported. Assembly/Break rows and special top-right links from that reference are not automatically added.

Preview and published snapshots share the same presentation model and class filter. Module titles link to the resolved meeting in HTML and PDF. Draft exports are labelled DRAFT PREVIEW with proposed effective date; historical exports show publication version and effective date. Cancelled historical lessons do not expose an active link.

Exports are generated locally in the browser. PNG files can be shared through supported device sharing or downloaded. PDF uses the same rendered layout with link annotations over module names; its visual text is rasterized, so it is not selectable text. Images cannot contain clickable links. Wide schedules split across weekday groups, long schedules paginate with repeated headings, and oversized cells ask the admin to filter by class. A locally hosted pdf-lib 1.17.1 bundle and MIT license are included; no external PDF service receives names or Zoom URLs.

## Verification and acceptance

- Complete regression suite and focused tests for multi-user batches, no partial write on invalid groups, conflict identity, moved-row recovery, revoked admin access, confirmed teacher eligibility and removal.
- Real bundled Cloudflare Worker/SQLite execution against synthetic Google Sheets, including batch writes, stable retries, subject rename and future publication.
- Browser UI logic exercised with the existing DOM test harness: retained edits, row saves, Save all, new-user pinning, subject rename conflict, copy previous timetable, protected draft and new version.
- Synthetic export generated with the actual presentation code and a native canvas. The sample PDF was rendered and visually inspected; all 15 meeting links verified. A dense schedule produced five pages with link rectangles inside page bounds.
- Interactive browser acceptance remains open: the previously reported browser security verification was unavailable. No alternative browser route was used to bypass that restriction.

Suggested user checks: edit multiple profiles and role cells then Save all; rename a subject; assign a Teacher role and refresh the timetable; preview a class and test its PDF link; edit a previous version and publish with a future effective date. Live data was not used for automated writes.

# V105.3.1.2 — Program subject import correction

## Problem and result

V105.3.1.1 imported Reboot names into AcademySubjectList but stopped before creating ProgramSubjects links. Those names existed in the dropdown but were absent from the Program grid. Repeated imports correctly reused the catalogue names, so reload, sign-out and catalogue recovery could not make them appear as Program subjects.

The reviewed import now saves/reuses the selected Academy names and adds all missing Program links. Its button is **Import and add to this Program**. The grid refreshes after both steps and reports added versus already linked subjects. No real workbook rows are modified by installing this release.

## Use

1. Open the Development Program management screen and check the V105.3.1.2 badge.
2. Expand **Import subject names from Reboot** and choose **Review Reboot subjects**.
3. Select the required names, including any imported with the previous revision, and choose **Import and add to this Program**.
4. Confirm each selected subject appears once in the grid and remains after Reload.

Existing Academy names are matched using the existing Unicode, case and whitespace normalization. Source rows with matching names resolve to one canonical subject; repeated Program IDs are deduplicated. Previously linked subjects retain their IDs and status; archived links are not silently reactivated. Different spellings remain distinct. Legacy Global-based rows still require explicit mapping through Edit so dependent levels/modules retain their historical ProgramSubjectID.

## Recovery and consistency

Catalogue recovery completes an interrupted catalogue write using its saved intent and receipt. If there is no pending intent, the screen now says so. It does not refresh, import, or attach subjects to a Program. **Retry same import** finishes the pending import flow.

The two workbooks are saved in two coordinated phases, not one cross-workbook transaction. The browser retains the exact catalogue request/result and Program request in session storage; the server stores separate durable intents and receipts. A response lost after either commit can be retried without duplicate names or links. Pre-fix catalogue-only pending requests retain their original operation IDs when resumed. If another edit invalidates the Program revision or catalogue reference revision, no bulk links are saved; the screen asks the administrator to review and select again. The already saved catalogue names are reused.

Bulk links use the existing manage-save route with kind subject-import and record.subjectIds (1–250 selected IDs). The server validates all active Academy subjects before planning an atomic Program snapshot/receipt append. Existing permission, Program status, reference revision and 40,000-character snapshot limits still apply. Existing records, modules, classes, memberships and published timetable history are preserved.

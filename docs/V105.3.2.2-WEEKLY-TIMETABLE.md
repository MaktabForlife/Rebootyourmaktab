# V105.3.2.2 — Weekly timetable corrections

## Behaviour

The Program timetable is an ongoing weekly pattern. Every lesson row repeats on its chosen weekdays until a newer timetable takes effect. The editor contains Module, Classes, Teacher, Weekdays, Start and End; there is no row-number, Pattern, first-date, last-date, date-window or exceptions column/section. Classes displays every selected class name. Optional levels remain part of module selection.

Teachers are optional. A blank teacher is shown as Not assigned and creates no teacher clash. A selected teacher must still be active and eligible. Class clashes and known learner-membership clashes continue to block publication; different unassigned lessons do not falsely share a teacher.

Time entry accepts 845, 0845, 8h45 and 8:45 as 08h45, and 1015 as 10h15. Existing saved shorthand is normalized when loaded. Display formatting happens when leaving the field; stored times use HH:mm. Invalid minutes, hours and reversed time ranges are still rejected.

One Effective from date appears in the publication preview. It defaults to today in the Program timezone; the administrator may choose a future date. Backdating is disallowed to protect published history. Saving a draft never changes the active timetable. Changing the effective date requires another preview so membership checks use that date. Publication is also revalidated against current references and memberships.

## Storage and compatibility

Weekly drafts and publication snapshots use `105.3.2.2-weekly`. The existing append-only state, publication and operation tables and serialized coordinator remain in use; no new workbook tabs, bindings or migrations are required. Every publication snapshots names, classes, optional teacher, weekly rules and its effective date. It has no end date or occurrence cap based on a date window.

The stored CurrentPublicationID points to the latest publication write. Reads derive the timetable in effect from immutable history: choose the newest published version whose effective date has arrived. A later published version takes precedence, so an older future version cannot reappear after a newer version. Same-date replacements use the latest version. History also reports derived end dates and Current / Scheduled / Past / Superseded status. Activation requires no scheduled job or rewriting of history. `published` accepts an optional date for resolving the applicable version.

Old dated snapshots retain their original dates and immutable contents. An expired old publication does not become an indefinite weekly timetable. Old recurring draft rows load into the weekly editor with their weekdays and times retained. If a saved draft includes one-off lessons or dated exceptions, it requires an explicit Use weekly lessons choice; the original remains downloadable and preserved in prior state. Older cached clients can still save their unfinished dated draft so upgrading does not lose edits; publication requires the new weekly editor. Already committed operations can replay their original receipts safely.

Browser-session storage retains unfinished weekly edits and exact pending requests, including the publication date, across a reload. A retry never selects a new effective date or operation ID. Overview learner counts use current active memberships in the draft's scheduled classes, deduplicated across combined classes.

The separate Academy access matrix remains in setup/review mode; this patch does not activate its role settings in legacy authorization or timetable teacher eligibility. No D1 migration is performed.

## Verification and acceptance

Verification passed: 80/80 regression files, development dry-run build, and the final bundle in the local Cloudflare/SQLite runtime. Automated coverage includes UI event tests for shorthand time entry and optional teachers, future activation at Program midnight, indefinite weekly validity, same-date/out-of-order replacements, class and learner conflicts, preserved historical snapshots, old-draft conversion and lost-acknowledgement recovery. Development bundle and local Cloudflare runtime API checks use synthetic spreadsheet data, never actual curriculum changes.

Browser visual acceptance is still pending: the browser security-policy verification service was unavailable during this work. User testing must verify desktop/mobile presentation and the real timetable flow. Earlier management and profile testing remains open.

Only `feature/v105.2-program-timetable`, `maktab-development` and `devrebootworker` are targeted. Main and the live deployment are excluded.

# Academy Course administration — V106.3

Global Admins have Course management and Course scheduling links in Academy administration, the Workshops chooser and individual Course pages. Both open `/academy/courses/manage/`; `?view=scheduling` selects scheduling directly. The wrapper checks the existing account session and the server-issued PLATFORM/GLOBAL_ADMIN context before displaying the editors. D1 endpoints independently authorise every request. A sign-out or account change hides and clears protected content, and late responses cannot reopen it.

The existing Course/Module, Task, Course access and delivery/scheduling editors are reused. Successful writes invalidate the other editor’s cached data. Unsaved Course/Module edits must be saved or explicitly discarded before opening scheduling. Existing scheduling draft review and retry identifiers remain in use. The unbuilt private media subscription editor is not exposed here; the live Library remains PUBLIC_ONLY.

The User profiles conflict view identifies the user and Program and displays saved and proposed values without a horizontally scrolling table. Its message describes an older draft without attributing the change to another administrator. Refreshing retains draft revisions; an actual intervening role change is still rejected until the administrator explicitly reviews and saves or discards the draft. First and repeat saves pass synthetic D1 integration tests. The specific cause of the reported live conflict has not been established.

Validation: existing editors opened with synthetic Academy Global Admin credentials; non-global roles rejected; first/repeat/conflicted Program-role saves and explicit conflict resolution tested through the real Worker/D1 HTTP contract. Release checks also cover account changes, Course editor navigation, responsive rendering, Worker build, version/cache alignment and deployment binding preservation. No database migration, live role change or credential change is part of this release.

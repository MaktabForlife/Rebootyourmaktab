# V105.3.4 — Assisted manual timetable planner

This historical revision is superseded by [V105.3.4.1 timetable boards](V105.3.4.1-TIMETABLE-BOARDS.md).

Development branch: `feature/v105.3.4-timetable`. This version adds planning aids to the existing ongoing weekly timetable draft. Administrators still choose every lesson placement. The published timetable continues to use the existing preview, effective-date and immutable publication flow.

## Use

1. Open a draft Program timetable. Set up the number of periods, first start time and usual duration. Adjust individual start and end times to allow breaks or a different period length. The same period grid applies to each weekday; lessons in the detailed grid can still use exact times outside these periods.
2. Select each eligible teacher. On their weekly grid, cycle a cell between Available, Preferred and Unavailable. Optionally set a maximum weekly teaching time using `12h30` or decimal hours. An unset limit imposes no ceiling.
3. Add each class, subject or module, teacher and required weekly teaching time. Enter durations such as `3h20`. The requirement list shows scheduled time and time remaining. A combined-class lesson counts towards the requirements of each included class when its subject/module and teacher match.
4. Select a class and requirement on the planning board. Tap an empty period to place a lesson. Tap an existing lesson and another period to move that weekday's occurrence. Undo reverses the last board placement or move. The detailed lesson grid remains available for combined classes, Zoom links, times outside the period grid and removing lessons.
5. Save the draft, validate and preview before publication. The planner settings and lessons use the existing coordinated draft save and recovery path. Planner settings are excluded from published snapshots.

## Guidance and validation

The board explains why a proposed placement is unsuitable: teacher unavailability, a break, an occupied class or teacher, a known learner enrolled in both classes, or a weekly teacher-hour ceiling. Preferred periods are marked. Repeated placements with the same class, teacher, subject/module and time are stored as one weekly lesson row with multiple weekdays.

Server validation checks period time ranges and overlaps, references to active teachers/classes/subjects, teacher unavailability, weekly limits and unmet teaching requirements. An invalid plan can be saved as a draft, but cannot be published. Changing availability after scheduling a lesson exposes a publication issue rather than silently moving the lesson. Existing class, teacher, break, Zoom and learner conflict checks still apply.

## Current boundaries

This planner works within one Program's timetable and teacher list. Cross-Program teaching commitments are not available to its placement checks. Period times are common across weekdays. The current draft supports at most 100 lesson rows; a row may cover several weekdays, so 100 rows can represent more than 100 weekly lesson occurrences. The existing 40,000-character draft/snapshot storage limit still applies. A schedule needing more distinct rows or a larger saved version requires a later storage expansion.

This is development work. It has not been deployed or accepted with an Academy's actual timetable.

## Verification

The planner regression checks normalization and compact availability for 15 teachers across 8 periods and 5 days; server review of unavailable teachers, hour limits, outstanding requirements and overlapping periods; draft persistence and older-editor preservation; and board placement, blocked placement, move and undo. Existing timetable UI, API and domain tests remain applicable. Browser visual acceptance is pending because the browser's security policy check was unavailable during development.

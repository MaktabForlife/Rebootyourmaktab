# V105.4 — Program curriculum and Library management

The Library work is rebuilt on `feature/105.3.4.13` at `01351c2`, preserving the V105.3.4.13 timetable planner and its later fixes. Basic Program subject, optional level and module entry arrived in V105.3. V105.4 extends the Reboot curriculum structure with task definitions under a subject and optional module. It also adds Program Library resource management using the same five categories as Reboot: eBooks, Printables, Audio, Video and Other. Resources are organised by Program subject, optional level, module and task. A module's level must match the resource's level. “General” resources can be attached to a subject without a module.

## Administrator workflow

Open **Program management → Tasks** to add, edit or archive curriculum tasks beneath a subject or module. Then open **Programs → Manage Library** or **Program management → Manage Library**. Choose **Add resource**, select a category and Program subject, and optionally select a level, module and task. To attach an existing file, choose **Add from Google Drive** and browse in the centered dialog. To upload a new file, choose **Add from device**, pick a local file, choose its destination in the Drive dialog, sign in to Google, and select **Upload into this folder**. Review the name and placement, then save the resource. The category, subject, module and task structure is shown in the Library list. Edit a resource to change its placement, file, name, description or Active/Archived status. Archived resources remain in the management list.

Only a freshly revalidated Academy `GLOBAL_ADMIN` can browse, save or preview Program Library files in this stage. A resource file must remain inside `M4L_GOOGLE_DRIVE_ROOT_FOLDER_ID` or a separately added Library root for that Program, and have a MIME type supported by its category. The service account must be able to read each selected folder. Existing Program management coordinator journalling, per-row revisions and operation receipts protect concurrent saves and uncertain responses. An active task or resource blocks archiving or moving its parent curriculum row until it is moved or archived.

Choose **Prepare Library tables** once. This adds `ProgramTasks` and `ProgramResources` to the configured Program spreadsheet without changing existing curriculum rows. Tasks and resources are individual rows, outside the bounded `ProgramManagementState` snapshot. Additional root IDs are kept in the Program management state. The Library screen preserves an unsaved entry and a retry identifier in session storage; a lost response can be confirmed with **Retry same save**.

## My Drive device upload setup

The existing service account has read-only Drive access and cannot own new files in a personal My Drive. Device upload therefore uses a short-lived Google OAuth token in the administrator's browser. The administrator chooses a Google account with permission to add files to the selected folder. The token is kept in browser memory; it is sent to Google's Drive API and is never sent to the Worker or stored in the Program spreadsheet. The newly uploaded file inherits the destination folder's sharing, so the service account still needs read access for resource verification and preview.

Set up a Google OAuth **Web application** client in the Google Cloud project with the Drive API enabled, an OAuth consent screen, and the Development Pages origin in **Authorized JavaScript origins**. Configure the client's public ID as the Development Worker's `M4L_GOOGLE_DRIVE_UPLOAD_CLIENT_ID` variable; keep any client secret out of Pages and Worker variables. If the OAuth consent screen is in testing mode, add the intended administrator Google account as a test user. The upload flow requests the `https://www.googleapis.com/auth/drive` scope because the administrator can select a pre-existing My Drive folder in the Library browser. Google may require app verification or a security assessment before wider use of this scope. Uploads use Google's resumable Drive API directly from the browser. The administrator must finish the Google sign-in and consent before the upload proceeds.

After configuring the variable, redeploy the Development Worker and test with a small PDF: upload into the selected My Drive folder, confirm it appears there, save the resource, reload the Library and open its protected preview. Test an account without write access to confirm it cannot upload. A failed resource save can leave the uploaded file in Drive; remove it there if it is no longer needed.

## Access boundary

V105.4 provides administrator management and preview. It does not activate the Academy access matrix as operational Program student authority or add Program resources to the unified student Library. That belongs to V105.5 student/program integration. The existing Reboot and Global Libraries continue using their current access routes and records.

# V105.4.2.4 — Program curriculum and Library

The Program Library runs on `feature/105.3.4.13`. It uses Reboot's eBooks, Printables, Audio, Video and Other categories. Resources are attached to a Program subject and optionally a level, module and task. eBooks may have an author, publisher, ISBN, publication year and cover image. V105.4.1.1 made device uploads resumable after temporary rate limits; V105.4.1.2 restored Save resource after an upload; V105.4.1.3 adds teacher uploads and one Resources folder for all Programs. The V105.4.1.3 review removed shared-link copying. V105.4.1.5 added web image search using title, author and publisher. V105.4.1.6 lets a user paste an image directly into the Library cover flow.

## Teacher and administrator workflow

Open the Program Library from the Academy account page. Start with **Add from device** or **Add from Library Drive** at the top of the page. Choose a category in the upload or Drive dialog, then complete the subject and optional level, module and task in the resource form.

- **Add from device** opens the computer's file picker, which can include Google Drive folders mounted on that computer. Confirm **Upload to Resources** in the centered dialog. The Library Google account owns the uploaded copy.
- **Add from Library Drive** opens the centered dialog to browse the app's Resources folder and its subfolders. Select a file already there. No duplicate is made.
- **Find cover online** in an eBook's details opens a dialog with its title, author and publisher prefilled. **Search images** opens Google Images in a new tab. Copy a suitable image, return to the Library, click the paste area and press ⌘V or Ctrl+V. The image enters the normal upload to Resources; save the resource to keep its new `CoverDriveFileID`. **Paste cover** opens the same paste area without first searching. Device and Library Drive cover options remain available. Copy the image itself: an image URL or pasted text is not imported.
- Review the resource details and choose **Save resource**. An upload is a separate Drive operation, so an unsaved resource may leave a file in Resources.

A teacher, senior or Program administrator must have an active role in the Program's Academy access matrix. The signed-in Academy account may currently be in another Course context; the Library checks Program access directly. A global administrator can manage every Program. The Library link on the Academy account page lists accessible Programs.

## Read-only viewer

V105.4.2 adds **Open Program Library** on the Academy account page and **View Library** in the resource manager. The viewer follows Reboot's Library pattern: subject choices, category filtering, module ribbons and resource cards. It shows book covers and metadata, and opens protected PDFs, audio, video and images using short-lived links. V105.4.2.1 shows only the media icon and title below a cover; fuller metadata remains in the resource preview. V105.4.2.3 enlarges cover images to fill more of each card while preserving their proportions. Cover links are requested only when their cards enter view. Other file types have a protected **Open file in new tab** link. The viewer never returns Drive file IDs in its catalogue.

V105.4.2.3 also makes both class membership dates optional. An assignment without dates is ongoing; either date may be added to limit the membership period. Timetable learner conflicts and Program overview counts include undated memberships.

## Bulk eBook upload

V105.4.2.4 adds **Bulk add eBooks** on the Library management page. A teacher or administrator can select up to 25 PDFs from the device, choose one subject and optional level, module and task for the batch, and review each book's title, description, author, publisher, ISBN, publication year and optional JPG, PNG or WebP cover. The app uploads and saves one book at a time into the designated Resources folder. If an upload or save stops, **Continue bulk upload** resumes the current file or retries the same save without adding a duplicate entry. Keep the page open while the batch runs. Saved books remain in the Library if a later book needs correction.

Program staff and global administrators can view all active resources. In V105.4.2.2, an account with an active, confirmed **STUDENT** Program role can also view active resources without a class enrollment, even while the Program remains in Draft. The Program appears in the account's access list and Library links. Class enrollment remains separate for class features. A student cannot open the management page. Archived resources and inactive curriculum references remain hidden. Removing the Program role or deactivating the account revokes Library access. Program teaching and other learner features remain in preparation.

## Resources folder

`SystemConfig!ProgramLibraryDriveFolderId` identifies the one Resources folder for all Programs. New device uploads always go there; Library Drive selection is limited to that folder and its subfolders. Only a `GLOBAL_ADMIN` can change it on the Library page. The Library Google account needs permission to add files; the Worker service account needs permission to read them. Keep General access **Restricted**. After changing the folder, run `authorizeM4LServices` in the Development Apps Script editor to confirm that its deploying account can add files. Earlier folder IDs are retained in `SystemConfig!ProgramLibraryPreviousFolderIds` so previously saved resources remain readable.

The Worker checks the Program and resource type before signing a short-lived upload request to Apps Script. Apps Script uses the deploying account's Drive authorization to start device uploads. The Google OAuth token and `M4L_LIBRARY_BRIDGE_SECRET` stay on the server. The Worker checks the final file's category and folder when the resource is saved. Existing resource rows and old Program Library roots remain readable.

## Development setup and checks

The V105.4.2.4 Library uses the existing protected Drive delivery and needs no Apps Script changes beyond the V105.4.1.3 deployment. Keep `appsscript.json` as deployed already; it includes the required Drive and external-request scopes. The Worker needs `APPS_SCRIPT_URL` and the same `M4L_LIBRARY_BRIDGE_SECRET` that is stored as an Apps Script Script property. Do not put the secret in Sheets or browser code.

1. Confirm `authorizeM4LServices` reports `libraryCanAddFiles: true` for the configured Resources folder.
2. Sign in as a Program teacher. Upload a small PDF from the device, save the resource, reload and preview it. Then choose an existing PDF from Library Drive and save it as another resource.
3. Search for a cover by title, author and publisher. Copy the image itself, paste it into the Library, upload it to Resources and save the eBook. Confirm the cover and book metadata survive reload. Also try pasting a URL to confirm the app asks for an image, and try a Library Drive cover.
4. Confirm the teacher cannot change the Resources folder or prepare Library tables. Check a global administrator can change the destination without losing access to existing resources.
5. Confirm unsupported file types and an outside-folder file ID cannot be saved. Check Reboot and Global Library access still works.
6. Sign in as a Program teacher and a student with a confirmed Program role but no class enrollment. Confirm the Program appears in the student's account and the viewer opens. Browse subjects and categories, then open a PDF and its cover. Remove the Student role or archive the resource and confirm access is denied on refresh and on a new open request.
7. Choose **Bulk add eBooks**, select two small PDFs, choose their shared subject and enter distinct titles. Add a cover to one, upload and save, then confirm both appear in the resource list and viewer with the expected metadata. A retry after a temporary error should continue the current book without creating a duplicate.

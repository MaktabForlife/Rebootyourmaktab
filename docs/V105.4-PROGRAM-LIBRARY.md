# V105.4.1.1 — Program curriculum and Library management

The Library work is rebuilt on `feature/105.3.4.13` at `01351c2`, preserving the V105.3.4.13 timetable planner and its later fixes. Basic Program subject, optional level and module entry arrived in V105.3. V105.4 extends the Reboot curriculum structure with task definitions under a subject and optional module. It also adds Program Library resource management using the same five categories as Reboot: eBooks, Printables, Audio, Video and Other. Resources are organised by Program subject, optional level, module and task. A module's level must match the resource's level. “General” resources can be attached to a subject without a module.

V105.4.1.1 keeps the same Library features and improves device uploads: a temporary Google Sheets rate limit during chunk transfer no longer discards the upload position, so the same upload can be retried after the limit clears.

## Administrator workflow

Open **Program management → Tasks** to add, edit or archive curriculum tasks beneath a subject or module. Then open **Programs → Manage Library** or **Program management → Manage Library**. Choose **Add resource**, select a category and Program subject, and optionally select a level, module and task. To attach an existing file, choose **Add from Google Drive** and browse in the centered dialog. To upload a new file, choose **Add from device**, pick a local file, choose its destination in the Drive dialog, and select **Upload into this folder**. eBooks also have optional author, publisher, ISBN, publication year and cover image fields. A cover can be selected from Drive or uploaded from the device; it appears beside the book in the Library list. Review the name and placement, then save the resource. Edit a resource to change its placement, file, details, cover or Active/Archived status. Archived resources remain in the management list.

Only a freshly revalidated Academy `GLOBAL_ADMIN` can browse, save or preview Program Library files in this stage. A resource file must remain inside `M4L_GOOGLE_DRIVE_ROOT_FOLDER_ID` or a separately added Library root for that Program, and have a MIME type supported by its category. The service account must be able to read each selected folder. Existing Program management coordinator journalling, per-row revisions and operation receipts protect concurrent saves and uncertain responses. An active task or resource blocks archiving or moving its parent curriculum row until it is moved or archived.

Choose **Prepare Library tables** once. This adds `ProgramTasks` and `ProgramResources` to the configured Program spreadsheet without changing existing curriculum rows. Existing `ProgramResources` tables gain the five book-detail columns on the first metadata save or when preparation is repeated; saved resource rows are preserved. Tasks and resources are individual rows, outside the bounded `ProgramManagementState` snapshot. Additional root IDs are kept in the Program management state. The Library screen preserves an unsaved entry and a retry identifier in session storage; a lost response can be confirmed with **Retry same save**.

## My Drive device upload setup

The Library Drive account and the app's existing Apps Script deployment account are the same. Device upload uses that deployment's Drive authorization, so the administrator does not need a second Google sign-in or an OAuth Web client. The Worker checks the signed-in Academy `GLOBAL_ADMIN`, Program, allowed root, folder and file type, then signs a short-lived request to Apps Script. Apps Script starts a Google Drive resumable upload using the deploying account's token, returning only the upload session URL to the Worker. The Worker sends encrypted upload tickets to the browser and relays file chunks to Google Drive. The Google OAuth token and shared secret never reach the browser. The service account still needs read access to the selected folder for browsing, verification and protected preview.

Synchronize the complete repository `apps-script/code.gs` and `appsscript.json` to the **Development** Apps Script project, then create a new web-app deployment or update the existing deployment. It must run as the deploying Library account. The manifest adds `script.external_request` so Apps Script can initiate the Drive upload. Run `authorizeM4LServices` in the Apps Script editor and grant the updated permissions. The Development Worker must retain `APPS_SCRIPT_URL` pointing at that deployment.

Generate one random secret of at least 32 characters and configure the same value as the Development Worker secret `M4L_LIBRARY_BRIDGE_SECRET` and the Development Apps Script **Script property** `M4L_LIBRARY_BRIDGE_SECRET`. Do not put it in Pages code, a spreadsheet, or the repository. Keep the Production Apps Script and Worker settings unchanged until this branch is accepted.

After configuration, redeploy the Development Worker and test with a small PDF: upload into the selected My Drive folder, confirm it appears there, save the resource, reload the Library and open its protected preview. Upload a JPG/PNG/WebP cover, save author, publisher, ISBN and year, then reload and confirm the cover thumbnail and details. Check that an outside-root folder, non-image cover, or file type unsupported by the category is rejected. A failed resource save can leave the uploaded file in Drive; remove it there if it is no longer needed.

## Access boundary

V105.4 provides administrator management and preview. It does not activate the Academy access matrix as operational Program student authority or add Program resources to the unified student Library. That belongs to V105.5 student/program integration. The existing Reboot and Global Libraries continue using their current access routes and records.

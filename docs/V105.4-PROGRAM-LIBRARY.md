# V105.4 — Program curriculum and Library management

The Library work is rebuilt on `feature/105.3.4.13` at `01351c2`, preserving the V105.3.4.13 timetable planner and its later fixes. Basic Program subject, optional level and module entry arrived in V105.3. V105.4 extends the Reboot curriculum structure with task definitions under a subject and optional module. It also adds Program Library resource management using the same five categories as Reboot: eBooks, Printables, Audio, Video and Other. Resources are organised by Program subject, optional level, module and task. A module's level must match the resource's level. “General” resources can be attached to a subject without a module.

## Administrator workflow

Open **Program management → Tasks** to add, edit or archive curriculum tasks beneath a subject or module. Then open **Programs → Manage Library** or **Program management → Manage Library**. Choose **Add resource**, select a category and Program subject, optionally select a level, module and task, then browse the configured protected Google Drive root. Enter a name and optional description, and save. The category, subject, module and task structure is shown in the Library list. Edit a resource to change its placement, file, name, description or Active/Archived status. Archived resources remain in the management list.

Only a freshly revalidated Academy `GLOBAL_ADMIN` can browse, save or preview Program Library files in this stage. A resource file must remain inside `M4L_GOOGLE_DRIVE_ROOT_FOLDER_ID` and have a MIME type supported by its category. Existing Program management coordinator journalling, per-row revisions and operation receipts protect concurrent saves and uncertain responses. An active task or resource blocks archiving or moving its parent curriculum row until it is moved or archived.

Choose **Prepare Library tables** once. This adds `ProgramTasks` and `ProgramResources` to the configured Program spreadsheet without changing existing curriculum rows. Tasks and resources are individual rows, outside the bounded `ProgramManagementState` snapshot. No new Worker binding or secret is required. The Library screen preserves an unsaved entry and a retry identifier in session storage; a lost response can be confirmed with **Retry same save**.

## Access boundary

V105.4 provides administrator management and preview. It does not activate the Academy access matrix as operational Program student authority or add Program resources to the unified student Library. That belongs to V105.5 student/program integration. The existing Reboot and Global Libraries continue using their current access routes and records.

# V105.3.1.7 — Refresh recovery and module rows

## Reported failure

During V105.3.1.6 testing, a management save succeeded but the following read returned `SHEETS_RATE_LIMITED` (reference `06f7438a-45ba-4bf5-809b-ef448fc254d2`). The UI correctly reported the save, but did not automatically retry the read. This response identifies a Google Sheets 429; it does not establish which quota was exhausted or the cause of earlier unrelated failures. The Cloudflare stored-log API rejected the existing credentials, so the matching historical log was not retrieved.

## Fix

- Show the acknowledged row immediately, using the saved record and its revision returned by the backend. Clearing the pending write happens before display/refresh work, so a display failure cannot turn an acknowledged write into an uncertain one.
- Retry a failed refresh automatically, with at least 60 seconds between attempts for a Sheets rate limit. Other temporary failures use short increasing delays. Stop after two automatic retries, keep the records and draft, and offer the existing Refresh records action.
- Retry only the read after a confirmed save. Never resubmit that save or call write recovery because its refresh failed.
- Keep browsing, row editing and draft storage available during the delay. Pause network actions until the scheduled refresh to avoid repeated clicks consuming quota. Preserve a draft started during the delay, including its comparison revision.
- Apply the same refresh recovery to manual/initial loading, preparation and confirmed subject imports. Non-retryable access/setup errors do not automatically retry. No credentials or real learner/curriculum records are changed.
- Share spreadsheet metadata reads only within one request, with defensive copies and invalidation after writes. Batch account and role reference reads. The synthetic management/overview fixture now uses 9 upstream reads, down from 13 in V105.3.1.6; this is a fixture measurement, not a universal production count or a guarantee that quotas cannot recur.

## Module rows

Subjects and levels remain collapsed by default. Opening either immediately shows its modules as rows with Module, Classes, Teachers, Learners and Actions columns. Modules no longer require a separate expansion. Unlevelled modules appear under the subject; empty subjects/levels retain their Add module action. Existing responsive table styling adapts the same controls into labelled rows on phones. Module editing, class status, timetable links, search and remembered subject/level expansion remain available.

# V105.2 — Timetable storage and API contracts

Program identity remains `105.1-program`; Platform schema stays `102.0.12`. The optional timetable extension identifies itself as `105.2`. Preparation atomically creates/repairs missing or empty tables after validating every populated existing table. It never replaces incompatible data or adds synthetic rows.

Exact headers are defined by `TIMETABLE_HEADERS` in `backend/src/programs/timetable-model.js`:

| Tab | Header order |
|---|---|
| ProgramSubjects | ProgramSubjectID, CourseID, SubjectID, Active |
| ProgramLevels | LevelID, ProgramSubjectID, Name, SortOrder, Active |
| ProgramModules | ProgramModuleID, ProgramSubjectID, LevelID, Name, SortOrder, Active |
| ProgramClasses | ClassID, CourseID, Name, AcademicYear, Active |
| ProgramEnrollments | EnrollmentID, CourseID, ClassID, AccountID, StartDate, EndDate, Active |
| ProgramTimetableState | Revision, CourseID, SchemaVersion, Sequence, DraftJSON, CurrentPublicationID, ModifiedDate, ModifiedByAccountID |
| ProgramTimetablePublications | PublicationID, CourseID, VersionNo, PublishedDate, PublishedByAccountID, SnapshotJSON, OperationID |
| ProgramTimetableOperations | OperationID, PayloadHash, ResultJSON, DateStamp, AccountID, Action |

The first column is unique and nonblank in each populated table. State rows are append-only. The row with the greatest valid unique Sequence is authoritative; its CurrentPublicationID must resolve to a complete publication in the same Program. A draft save copies the existing current pointer; a publish allocates a new publication UUID/version and advances the pointer. There is no mutable singleton pointer for a delayed request to overwrite. Publication and receipt rows are never edited by later operations. Sheets strings use literal `stringValue`, including JSON and labels.

DraftJSON stores timezone, startDate, endDate, rules and exceptions. A rule has stable `RULE-…` id, RECURRING or EXPLICIT kind, moduleId, teacherId, distinct classIds, weekdays (0 Sunday–6 Saturday), first/last dates and HH:mm times. Each `(ruleId, classId)` pair is a stable audience association. A combined lesson is one rule/occurrence with multiple audiences. Exception IDs use `EX-…`, ruleId, originalDate, CANCEL or MOVE, and optional replacement date/time.

Occurrence identity is `ruleId@originalDate`, independent of audiences and publication version. SnapshotJSON additionally captures Program name, Program subject/shared subject IDs, module/subject/level names, level ID, teacher name and class names aligned with their IDs. Historical occurrences derive exclusively from this snapshot; they do not consult the current catalog. No attendance or progress data is merged or created here.

Every endpoint is POST under `/api/admin/platform/program-timetable/`, requires central GLOBAL_ADMIN and returns no-store JSON. Requests are capped at 64 KiB before JSON parsing.

| Operation | Contract |
|---|---|
| get | Program ID; returns readiness, draft, revision, references, current publication ID and history summaries. |
| prepare | Program ID; coordinator prepares empty extension tables. ProgramIdentity must already be valid. |
| save | Program ID, current revision, draft, UUID v4 operationId. Allows incomplete drafts. |
| validate / preview | Program ID and draft; same validation/derivation/conflict engine as publication. No mutation. |
| publish | Program ID, current revision, draft, UUID v4 operationId. Full current reference/time/conflict validation; atomic new snapshot/state/receipt. |
| history | Program ID; immutable versions and derived occurrences, plus current pointer. |
| recover | Program ID; finishes any persisted earlier intent under fresh administrator authority. |

The service’s internal `published` reader resolves only the pointer-selected complete immutable snapshot. It is deliberately not exposed as a student endpoint until V105.6 account/class filtering is implemented. Legacy Reboot routing rejects the new Program schema, as in V105.1.

Repository reads batch the available Program tables. Existing request-local read deduplication is retained; each queued mutation gets a fresh request environment and fresh authentication. Teacher eligibility is derived from central active account plus active same-Program grants. Minimum reference readers precede full V105.3 membership enforcement and V105.4 management.

`ProgramTimetableCoordinator` is named using canonical Platform spreadsheet ID and canonical Program ID. Its SQLite `pending` table has one bound-parameter JSON intent row; no auth token is stored. In-memory promise sequencing handles concurrent external I/O; the durable journal preserves recovery across object eviction. This is real write coordination, in addition to revision comparison. Receipt hashes use canonical JSON and reject operation-ID reuse with a different action/payload. Grid growth appends blank rows only; retrying growth can add harmless unused rows but never shrink a sheet or move saved records.

Runtime architecture follows Cloudflare’s [Durable Object namespace/RPC](https://developers.cloudflare.com/durable-objects/api/namespace/) and [storage coordination guidance](https://developers.cloudflare.com/durable-objects/best-practices/rules-of-durable-objects/). External Sheets I/O is not held inside blockConcurrencyWhile. One object coordinates one Program; this does not provide a cross-Program lock or cross-Program conflict detector.

# V105.3.1.3 — Desktop rows and mobile cards

Program management opens on Overview: Subject, Level, Module, Classes, Teachers, Learners and Actions appear together. One module occupies one row on large screens. At 760px and below, the same table becomes labelled cards, with no duplicate controls or separate mobile data. The existing six management sections also become cards.

Subjects without modules and levels awaiting modules remain visible. Add module opens a new record with the subject and optional level selected. Edit module opens the existing editor. Subjects, levels, classes, teachers and learner memberships remain maintained through their management sections. Timetable links lead to lesson scheduling; the overview does not introduce a second assignment system. Levels remain optional and independent of years.

Classes and teachers aggregate the selections in the saved timetable draft. Learner lists show distinct account IDs with active class membership on at least one scheduled module lesson date in the draft window. Combined classes do not duplicate the same learner, and cancelled lessons do not contribute membership. Invalid or unavailable timetable data displays a notice and unavailable learner counts rather than silently showing an empty roster. These are draft planning relationships, not published learner access or attendance.

Search covers subjects, levels, modules, class/teacher names and learner names. Archived curriculum remains labelled. Unknown references remain visible for repair. Pending row saves restore their editor; pending imports restore Subjects so their retry controls remain accessible.

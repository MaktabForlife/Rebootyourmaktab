# V106.10 release checks

Global status is a searchable editor in User profiles. Global Admin authority is independent of scoped assignments and automatically applies to all Programs and Courses. Global Teacher is a teaching-directory designation; access follows assignments. Another administrator must remove your own Global Admin designation.

Subjects and Modules are Academy-wide definitions. A Module belongs to a Subject; Program module rows are usage with their own unchanged IDs, levels, order and progress. Course categorisation uses the same definitions without changing lesson content or access. The central editor lists usage and preserves drafts, conflict reviews and exact retry receipts.

It promotes active Subjects used by active Programs, deduplicates active Modules by Subject and name, and leaves unknown Course parent Subjects for explicit classification. Existing scoped records, media references and immutable publications are preserved. Archiving a shared Module preserves existing usage. Apply 0010 before deploying this version. The main and test databases are backed up privately outside Git.

Verification covers Global Admin grant/revocation and transaction-time authority, self-removal and final-administrator protection, stale edits, shared definitions and independent usage, Course categorisation, migration deduplication and exclusions, resource/publication preservation, draft recovery and lost acknowledgements. ## Free-plan operation

The owner has chosen to retain Workers Free. On 10 October, a read-only runtime diagnostic confirmed D1 daily row-read exhaustion. Cloudflare's rolling 24-hour database totals were 4,190,286 test rows and 1,100,584 main rows. These are rolling totals, not an exact midnight-to-midnight split. Hosted testing used most of the combined allowance. All regression and capacity testing should run locally by default. Before a hosted smoke or capacity test, inspect the shared account allowance and bound the test's row budget; separate databases do not isolate this account quota.

Timetables now appear only on Academy home and its full timetable view. Program pages and the Course list have no timetable panel or polling timer. The public preview loads a public-only daily snapshot through GET /api/academy/entrance/public-snapshot. It has no background or tab-return refresh. A shared object in the existing MEDIA_BUCKET R2 binding survives edge eviction; edge/browser caching expires at the next UTC midnight. The first visitor after expiry creates the next seven-day snapshot. Concurrent first visitors can read D1 more than once, but conditional creation retains one snapshot. This is a marketing projection: only activity titles, dates and times are stored; all personal metadata, meeting information and media links are excluded. Public changes can take up to a day to appear. Protected HTTP responses retain private/no-store and fresh server-side authority checks. No new storage binding or billing change is needed.

Main query insights showed 402,370 row reads across 972 repeated activation checks, plus 99,094 reads checking the learning/course import tables. A bounded before/after read-only measurement on main returned 422 rows read for the old activation query and 114 for the replacement (73% fewer for this query, not the entire application). Required schema now compiles through zero-row projections rather than sqlite_schema scans; live migration, ownership and account guards still run. Optional-schema and import probes avoid table-list scans too. Course management loads cross-Academy teaching lessons only when validating, accepting, publishing or restoring an existing validation review. Listing, saving and participant editing no longer load clash data.

Signed-in home timetable data loads once per Academy day per signed-in session, on first opening or the next day. A tab-local cache bound to a hash of the current session survives reloads; signing out or switching accounts discards it. Each explicitly browsed week is cached separately, up to eight ranges. The Refresh button forces a current load. Joining/start/end boundaries only re-render the browser display; returning to a tab on the same day makes no timetable request. A new /api/academy/lesson/join endpoint resolves the immutable lesson reference using current account, roles, class enrolments, publication and lifecycle before releasing a meeting URL within its five-minute opening window. Cached schedules contain no meeting URLs. Permissions and schedule edits can appear stale until Refresh or the next day, but cached display grants no authority to join or edit. A failed refresh clears protected content and stops automatic retries. Daily D1 read exhaustion has a specific response code, UTC reset time and Retry-After header. The release does not change billing or restore an exhausted allowance. Verify live timetable recovery after the daily reset at 00:00 UTC.

Final local checks: 133/133 regression test files pass, including daily-cache isolation, manual Refresh, no fetch at lesson boundaries, day rollover, joining-window edges, current class membership, disabled accounts, Course cancellation and stable derived Course references. The development Worker dry-run build and browser layout/Refresh/reload checks pass. Migration 0010 is applied to main and test. The public-only daily snapshot was seeded from the private main backup without a runtime D1 query, so it can serve during the existing quota outage.

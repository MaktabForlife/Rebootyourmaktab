# V105.3.2.3 — Class and lesson Zoom links

Classes now includes an optional Zoom link field. The timetable has a Zoom link column for a lesson-specific meeting; a Classes shortcut opens the default-link editor. These fields accept HTTPS links, including a meeting passcode in the query string. Empty links are permitted for single-class lessons.

The lesson link always wins. Without an override, a single-class lesson uses its class link. A combined-class lesson must have a shared lesson link before publication, even if all participating classes have their own defaults. Drafts with missing links remain saveable. No class is selected arbitrarily and no global/reboot link is inherited.

The editor shows whether the link comes from the lesson or class. Preview cards, the lesson list and publication history include Open Zoom links. Links open separately; they do not select or edit the timetable row. Clearing a single-class lesson override restores the class fallback.

Class `ZoomLink` is stored in the existing canonical ProgramManagementState snapshot. Lesson `zoomLink` is stored in DraftJSON. Publication captures the resolved `effectiveZoomLink` and `zoomSource` in SnapshotJSON; displayed occurrences expose `zoomLink` and `zoomSource`. These optional additive fields retain the existing `105.3.2.2-weekly` storage format. No table/header migration, database provisioning or direct user-data edits are performed during deployment.

Class or draft link edits do not rewrite an existing publication; preview and publish a replacement to apply them. Historical versions without links remain without links. Cached clients omitting new fields preserve saved class/lesson links; clearing is an explicit empty value. Existing optimistic revisions, audit history, administrator authorization and retry receipts still apply.

Validation rejects non-HTTPS links, embedded URL credentials, control characters and oversized class links. Rendering also checks link safety before creating anchors. Meeting links are never automatically fetched or opened during validation/testing.

Verification passed: 81/81 regression test files, development dry-run build and local Cloudflare/SQLite runtime API checks. Coverage includes class and lesson save/read, override/fallback, combined-class requirements, explicit clearing, cached edits, lost-response retries, safe rendering and immutable publications. Development bundle and local Cloudflare API tests use synthetic workbooks.

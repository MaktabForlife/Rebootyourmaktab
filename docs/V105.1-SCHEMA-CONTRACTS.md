# V105.1 — Program schema and service contracts

## Storage added now

The existing `CourseRegistry`, `UserAccounts`, `UserCourseAccess` and `PlatformAuditLog` remain authoritative and retain their headers. `CourseID` is the stored Program ID. New IDs are `PRG-` plus a UUID v4, independent of names and row positions. The existing Platform schema version is unchanged; the new configuration table is an optional extension owned by the Program repository.

The Platform spreadsheet receives `ProgramDefinitions` only when a platform administrator saves the first new Program:

| Column | Meaning |
|---|---|
| CourseID | Exactly one matching `CourseRegistry` entry with schema `105.1-program`. |
| DurationYears | Blank/pending or integer 1–30. Aalimiya is four. No curriculum implications. |
| Timezone | Blank/pending or a timezone accepted by the runtime's `Intl.DateTimeFormat`. Used independently of the Google spreadsheet's own timezone. |
| Status | `DRAFT` or `ARCHIVED`; neither enables student access. |
| Revision | Opaque UUID replaced on each successful configuration update. Detects an already committed edit; not a lock. |
| ModifiedDate | ISO UTC timestamp. |
| ModifiedByAccountID | Authenticated central account ID. |

Name and fixed spreadsheet mapping remain exclusively in `CourseRegistry`. Creation audit fields and name changes use that registry's existing columns. Writes to registry, definition and audit log are one atomic Sheets batch within the Platform workbook. Strings are written as literal `stringValue`, never interpreted as formulas.

The Program spreadsheet receives only `ProgramIdentity`, with exactly one data row:

| CourseID | SchemaVersion |
|---|---|
| Same stable registry ID | `105.1-program` |

The pre-existing `Setup` tab is preserved. Preparation adds no accounts, learners, levels, modules, classes, sessions or sample curriculum. Existing incompatible populated tables are not overwritten. Setup in the two workbooks is not one cross-workbook transaction: an inactive registration can safely exist before its identity tab is prepared.

## API and adapter boundaries

All endpoints are POST under `/api/admin/platform/programs/` and require a freshly revalidated central `GLOBAL_ADMIN`. Local ADMIN authority is insufficient even if a local token claims a high role. Responses are `no-store`. Mutation bodies are bounded at 8 KiB.

| Operation | Input/result |
|---|---|
| `list` | Returns existing/new Program summaries and capability availability. No per-Program sheet fan-out. |
| `create` | Stable draft `id`, `name`, `spreadsheetId` or Sheets URL, optional `durationYears`, optional `timezone`, `status`. Returns the saved Program/revision; a matching repeated request returns it with `replayed=true`. |
| `save` | Existing `id`, current `revision`, name/duration/timezone/status; mapping changes refused. |
| `readiness` | `id`; checks application read access, identity schema and configured timezone. |
| `prepare` | `id`; safely prepares identity, rereads it and reports readiness. |

Domain validation and operations live in `backend/src/programs/model.js` and `service.js`. The storage boundary is `sheets-repository.js`: registry/definition reads, platform preparation, target inspection/preparation and atomic configuration commit. A future D1 adapter can implement the service contract without changing Program IDs. No D1 dependency is introduced now.

Capabilities are server-owned in V105.1: configuration enabled; timetable, membership, curriculum, library, attendance, progress and planner disabled. Enabling one later requires both an implemented service and its accepted policy. The client cannot turn these flags on.

## Relational contracts for later V105 stages — not created now

These identifiers and ownership rules carry the agreed model forward. Exact operational headers and audit columns belong in their implementing stages.

| Entity | Required identity and ownership | Constraint |
|---|---|---|
| Program subject link | `ProgramSubjectID`, `CourseID`, shared Academy `SubjectID` | One subject definition/name can be reused across Programs; unique subject link within a Program. Existing Reboot local subjects are not automatically merged. |
| Subject level | `LevelID`, `ProgramSubjectID`, label, ordering | Optional. A level belongs to this subject within this Program; it is not an academic year. |
| Program module | `ProgramModuleID`, `ProgramSubjectID`, nullable `LevelID`, label/order; optional reference to a common module definition | If LevelID is present, its ProgramSubjectID must match the module's. Modules with no level are first-class. |
| Class | `ClassID`, `CourseID`, label, optional intake/academic-year references | A delivery/enrollment group, independent of curriculum level. |
| Class enrollment | `EnrollmentID`, `ClassID`, `AccountID`, effective dates | Reuses central identity, keeps placement history, validates Program access. |
| Timetable rule / explicit session | Stable rule/session ID, `CourseID`, `ProgramModuleID`, teacher and schedule data | A teaching item refers to a module. Normal dated occurrences derive from recurring rules. |
| Session audience | Stable link ID, rule/session ID, `ClassID` | Multiple classes, including different years, may share one lesson; each must belong to the same Program. No duplicate lesson per audience. |
| Published timetable | Stable publication ID, immutable rules/explicit sessions, exceptions, audiences, labels and window/timezone | Students read only complete published versions; configuration or draft edits do not publish. |
| Teaching record | Stable ID, occurrence anchor, `AccountID`, relevant Program/class context | Attendance and progress remain individual even when classes share a lesson. |
| Library item/link | Stable resource/link ID plus authorized Program/subject/optional-level/module context | Follow existing Reboot browsing organization; sharing a definition or lesson does not grant unrelated access. |

Sequence remains V105 on Sheets → V106 Reboot migration on Sheets → later D1 migration → realistic capacity acceptance → wider rollout. Formal exams, promotion and graduation are outside this scope.

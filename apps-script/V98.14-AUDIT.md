# V98.14 final Apps Script audit

Date: 2026-08-05

This document records the V98.14 state. V105.4 later added the signed Program
Library upload action; see `README.md` and `MIGRATION-CHANGELOG.md` for the
current two-action bridge.

## Decision

M4L's database-management boundary is now explicit:

- the UI initiates every application data change;
- authenticated Cloudflare Worker routes own Google Sheets reads and writes;
- nothing outside the application calls Apps Script for Sheets maintenance;
- Apps Script remains only as the Weekly Planner Google Drive bridge.

`populateAllStudentTasks` was a one-time startup utility and is retired. Admin
registration/lookup, Task Resource administration and StudentTask compatibility
lookup represent either completed maintenance or features not yet built; any
future version must be implemented in the UI and Worker rather than restored to
Apps Script.

## Public web-app surface

The only callable `doPost` action is:

| Action | Purpose | Dependencies |
|---|---|---|
| `saveWeeklyPlannerPreviewToDrive` | Validate and save a Weekly Planner PNG in the configured Google Drive folder | read-only SystemConfig lookup, Drive config validation, PNG base64 extraction, filename sanitization, Drive file creation |

Unknown actions return an error response.

## Manual function

- `authorizeM4LServices` validates access to the bound spreadsheet and configured
  Drive folder. It performs no Sheet write and creates no Drive file.

## Removed in the final V98.14 pass

- `registerAdmin`
- `getAdminByUsername`
- `createTaskResource`
- `listTaskResources`
- `updateTaskResource`
- `populateAllStudentTasks`
- `getStudentTaskById`
- both `testPopulateAllStudentTasks*` functions
- every helper reachable only from those operations

## Retained function dependency closure

`code.gs` contains exactly nine named functions:

- `getSystemConfigValue_`
- `getWeeklyPlannerDriveConfig_`
- `extractWeeklyPlannerPreviewBase64_`
- `sanitizeWeeklyPlannerDriveFileName_`
- `saveWeeklyPlannerPreviewToDrive`
- `authorizeM4LServices`
- `doPost`
- `jsonResponse`
- `doGet`

The SystemConfig helper is read-only. No Sheet mutation method is present.

## Automated guard

`backend/tests/apps-script-cleanup.test.mjs`:

- parses `code.gs` as JavaScript;
- enforces the exact nine-function dependency closure;
- enforces the one-action public allowlist;
- prevents restoration of retired route and maintenance functions;
- rejects common Google Sheets mutation calls;
- confirms the SystemConfig read and Drive file-creation dependencies;
- verifies the required current-spreadsheet and Drive OAuth scopes.

Run with:

```bash
cd backend
npm run test:apps-script-cleanup
```

## Deployment gate

Production verification:

3. Routing diagnostics show migrated features as `google-sheets` with only
